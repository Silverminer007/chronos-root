# ADR-2026-10-21-004: Angular `core/` (Ticket #178)

Status: umgesetzt (Branch `angular-frontend`). Ergänzt ADR-2026-10-21-001 und ARC42 Abschnitte 5 und 8.

Entscheidungen:
- **Modelle:** `core/models/index.ts` ist ein 1:1-Port von `frontend/app/types/index.ts` (Feldnamen unverändert, snake_case bzw. camelCase wie im Backend).
- **Fehlermeldungen:** `core/errors.ts` ist der Port von `utils/errors.ts`. Zusätzlich wird `error.message` gelesen, weil Angulars `HttpErrorResponse` den Backend-Body dort ablegt (Nuxt: `data.message`). Reihenfolge: `data.message`, `error.message`, `message`, Fallback.
- **AuthService:** Signal `user`; `checkSession` (`GET /api/auth/isLoggedIn`, Erfolg = true), `fetchUser`, `updateProfile`, Konto-/Passkey-Methoden, `logout`. Die Methoden, die im Nuxt-Store `window.location.href` setzen (`changePassword`, `linkAccount`, `createPasskey`, `deletePasskey`, `updateProfile`), liefern die Keycloak-URL zurück; die Komponente navigiert per `redirectTo`. `logout` navigiert wie bisher immer auf `/`, auch bei Fehler. Das `SESSION_EXPIRED`-Signal des Service Workers (`listenForSessionExpiry`, in `App` aufgerufen) navigiert über den Router auf `/` (ersetzt `plugins/auth.client.ts`).
- **Profilprüfung:** `AuthService.isProfileComplete()` = Vor- und Nachname gesetzt. Der Guard leitet auf `/onboarding`, wenn das Onboarding noch nicht abgeschlossen ist (`OnboardingService`, Port von `useOnboarding`, gleicher localStorage-Schlüssel `onboardingShownAt`) **oder** das Profil unvollständig ist (CLAUDE.md: „profile incomplete“). Abweichung vom Nuxt-Code, der nur `shouldShow()` prüfte.
- **authGuard:** Funktionaler `CanActivateFn`, Port von `auth.global.ts` (nicht angemeldet: außer `/` und `/public/*` → `/`; angemeldet: Benutzer laden, Onboarding, `/` → `/agenda`). Der Guard wird in diesem Ticket nicht an Routen gehängt (es gibt noch keine geschützten Seiten); die Routen-Tickets nutzen ihn als `canActivate` bzw. `canActivateChild` der Wurzelroute.
- **HTTP-Interceptor (`errorInterceptor`):** zeigt nur für übergreifende Fehler einen deutschen Toast: Status 0 (keine Verbindung), 403, ≥ 500. 400/404/409 u. a. behandeln die Aufrufer selbst (Nuxt zeigte ebenfalls keine globalen Toasts); 401 ignoriert er, weil der Service Worker Token erneuert und Sitzungsende signalisiert; `/api/auth/isLoggedIn` ist ausgenommen, da jeder Fehler dort „nicht angemeldet“ bedeutet. Der Fehler wird unverändert weitergeworfen.
- **ToastService:** Signal-Liste, Auto-Ausblenden nach 3 s (`DEFAULT_LIFE_MS`, überschreibbar per `life`), Severities `success|info|warn|error` wie PrimeVue. Darstellung durch `ToastContainerComponent` (Bootstrap-`toast`-Markup, CSS-only ohne Bootstrap-JS), einmal in `App` eingebunden.
- **ModalService / ConfirmDialog:** `ModalService.confirm({title, message, confirmText, confirmColor})` liefert `Promise<boolean>` statt Props/Events wie in `ConfirmDialog.vue`; Farben `red|purple|green` (Standard `purple`, Gradient-Button der Marke). `ConfirmDialogComponent` rendert ein Bootstrap-Modal (ohne Bootstrap-JS) mit `role="dialog"`, schließt per Abbrechen und Escape, nicht per Klick auf den Hintergrund (wie im Nuxt-Dialog). Ein neuer Dialog bricht einen offenen mit `false` ab.
- **Tests:** je Service/Komponente ein Spec (Vitest über `ng test`), HTTP über `HttpTestingController`.
