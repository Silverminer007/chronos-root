## Context

Hibernate ORM is the standard for Java, but its API is verbose:

```java
// Standard Hibernate (not Panache)
var em = entityManager; // Inject EntityManager
var appt = em.createQuery("SELECT a FROM Appointment a WHERE a.id = ?1", Appointment.class)
  .setParameter(1, id)
  .getSingleResult();
```

Panache provides an **ActiveRecord** wrapper that reduces boilerplate:

```java
// With Panache
var appt = Appointment.findById(id);
```

## Decision

Use **Panache for ORM**, with Quarkus's built-in Panache extension. This gives us:
- **ActiveRecord pattern**: Entities have query methods directly (cleaner)
- **Fewer lines of code**: No EntityManager injection needed
- **Familiar API**: Similar to Rails ActiveRecord or Django ORM
- **Still uses Hibernate**: All the power of Hibernate, less boilerplate

## Consequences

### Positive
- ✅ **Reduced boilerplate**: No EntityManager, no QueryBuilders
- ✅ **Familiar pattern**: ActiveRecord is common in web frameworks
- ✅ **Still uses Hibernate**: All ORM features still available
- ✅ **Type-safe queries**: No string queries (we use PanacheQuery)
- ✅ **Easy pagination**: Built-in `page()` and `pageCount()`
- ✅ **Simple repository pattern**: Extend `PanacheRepository<T>`

### Negative
- ❌ **Entities tied to Panache**: Must extend `PanacheEntity`
- ❌ **Less explicit**: Magic methods on entities can be confusing for newcomers
- ❌ **Limited to Quarkus**: If we ever switch from Quarkus, we lose Panache
- ❌ **Queries still string-based**: String queries (no compile-time checking)

### Trade-offs
- **Convenience vs. flexibility**: Panache is convenient but less flexible than raw Hibernate
- **Magic vs. explicitness**: Panache's magic methods are convenient but less obvious
- **Vendor lock-in vs. productivity**: Panache ties us to Quarkus, but productivity gain is worth it

## Implementation Pattern

### Entities

All entities extend `PanacheEntity`:

```java
@Entity
public class Appointment extends PanacheEntity {
  @NotNull
  public String title;
  
  @NotNull
  public String organizerId;
  
  @OneToMany(mappedBy = "appointment")
  public List<Participation> participations;
}
```

### Repositories

Repositories extend `PanacheRepository<T>`:

```java
@ApplicationScoped
public class AppointmentRepository implements PanacheRepository<Appointment> {
  // Panache provides: findById, list, count, persist, etc.
  
  // Add custom queries
  public List<Appointment> findByOrganizer(String organizerId) {
    return list("organizerId", organizerId);
  }

  public List<Appointment> searchByTitle(String titleSearch) {
    return list("title ILIKE ?1", "%" + titleSearch + "%");
  }

  public Appointment findLatest() {
    return find("ORDER BY id DESC").firstResult();
  }
}
```

### Usage in Services

```java
@ApplicationScoped
public class AppointmentService {
  @Inject AppointmentRepository repo;

  public Appointment getById(Long id) {
    return repo.findById(id);
  }

  public List<Appointment> getByOrganizer(String organizerId) {
    return repo.findByOrganizer(organizerId);
  }

  @Transactional
  public Appointment create(CreateAppointmentDto dto, String userId) {
    var appt = new Appointment();
    appt.title = dto.title;
    appt.organizerId = userId;
    appt.persist(); // Save to database
    return appt;
  }

  @Transactional
  public void delete(Long id) {
    var appt = Appointment.findById(id);
    appt.delete();
  }
}
```

## Common Queries

### List All
```java
var all = Appointment.listAll();
```

### Find by ID
```java
var appt = Appointment.findById(appointmentId);
```

### Query with Parameters
```java
var upcoming = Appointment.find("startTime > ?1", LocalDateTime.now()).list();
```

### Pagination
```java
var page = Appointment.find("organizerId", organizerId).page(0, 10).list();
var count = Appointment.find("organizerId", organizerId).count();
```

### Update
```java
var appt = Appointment.findById(id);
appt.title = "New title";
appt.persist(); // Panache tracks changes automatically
```

### Delete
```java
var appt = Appointment.findById(id);
appt.delete();
```

## Testing with Panache

Tests can interact with Panache the same way services do:

```java
@QuarkusTest
public class AppointmentServiceTest {
  @Test
  void testCreate() {
    // Arrange
    var dto = new CreateAppointmentDto("Meeting", ...);

    // Act
    var result = appointmentService.create(dto, "user123");

    // Assert
    var saved = Appointment.findById(result.id);
    assertEquals("Meeting", saved.title);
  }
}
```
